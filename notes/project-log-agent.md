# Project log: building a research agent and a multi-agent pipeline

After the RAG pipeline, the project added tool use: a research agent that can search the notes, search the web and save new notes. This note records how it was built and what went wrong along the way.

The agent had three tools. query_notes searched the vector index and was written in the application. save_note wrote a new Markdown file. Web search used Anthropic's built-in server-side tool instead of a third-party search API such as Tavily, which kept the stack simpler: no extra API key and no HTML parsing code. The agent loop stopped after at most 10 steps.

The first web search tool version tried, web_search_20260318, includes dynamic filtering, where Claude runs code to filter search results. In a hand-written agent loop, it failed with the error "container_id is required when there are pending tool uses generated by code execution with tools". Switching to the basic web_search_20250305 version fixed it.

A note saved by the agent was not found by query_notes in the next question. Saving wrote the file to disk, but it never reached the vector index. The fix was to make save_note index the note immediately: chunk it, embed the chunks, delete any old chunks for that file and insert the new ones.

The agent did not always save its research, because the decision was left to the model. Explicit rules in the system prompt made the behaviour predictable: always query the notes before searching the web, and always save a summary note after researching a topic on the web.

A --confirm flag added a human-in-the-loop step: before saving, the CLI showed the file name and a preview and asked for approval. When the user declined, the agent received "User declined to save the note" as the tool result and simply answered without saving. Passing the user's reason back would let it adjust instead.

A second program turned the same tools into a multi-agent pipeline: a research agent with notes and web search, a writer agent and a reviewer agent, run in a fixed order and followed by saving the note. Because the order is hardcoded, it is a workflow with agent-like steps, not an agent.
